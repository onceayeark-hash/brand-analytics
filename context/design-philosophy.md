# BRAND ANALYTICS｜UI設計哲学書 v1.1
> 新しい画面・要素を実装する際は必ずこれを参照すること
> **哲学書は「実態の記録」。実装と食い違う場合は実装を優先し、哲学書を更新する。**

---

## このツールの本質
使用者はeBayセラーであり、すでにMy eBayの画面に慣れ親しんでいる。このツールはMy eBayの延長線上にあるべきであり、見慣れた安心感を保ちながら、My eBayにはない高機能を提供することが目的である。
**「高性能だが重くない・シンプルだが頼れる」がすべての判断の基準軸。**

## ① 空間・余白の哲学：「内容に従う」

### 原則
入力欄・表示枠のサイズは「中に入るコンテンツ」に従って決める。枠が内容を支配するのではなく、内容が枠のサイズを決める。

### コンテンツ別サイズ基準
| コンテンツ種別 | 入力欄幅 |
|---|---|
| 数値・パーセント・手数料率（5文字前後） | 80〜100px |
| 金額（$・¥）（最大7〜8文字） | 100〜120px |
| 商品名・タイトル（最大80文字以上） | 100%（横幅いっぱい） |
| ラベル・補足テキスト | 内容の長さに合わせる |

### テキスト配置の原則
- 文字・商品名・ラベル・説明文 → **左詰め**
- 金額・数値・パーセント → **右詰め**（桁が縦に揃い、比較が容易）
- ボタン内テキスト → **中央揃え**
- テーブルヘッダー → 列の内容に合わせる（数値列=右揃え、文字列=左揃え）
- 100%幅は商品名・タイトル入力欄のみ。数値・金額・パーセント入力欄には適用しない。

### 禁止事項
- 全要素を同じ幅に揃えること（内容無視の統一）
- 数値入力欄を不必要に横長にすること
- コンテンツが少ないのにカードを大きく取ること
- 数値を左詰めにすること

## ② データ表示の哲学：「データの性質でグラフを選ぶ」

### 原則
グラフの種類は「何を伝えたいか」で決まる。見た目の好みではなく、データの性質に最適なグラフを選ぶことが読み手への誠実さである。

### グラフ選択の判断基準
| データの性質 | グラフ種類 |
|---|---|
| 時系列の推移（月ごとの売上等） | 縦棒グラフ（別軸指標は折れ線で重ねる） |
| 構成比・シェアの比較 | 円グラフ（ドーナツ型推奨・最大8項目） |
| 2指標の対比（売上vs手数料等） | 並列縦棒グラフ（グループ棒グラフ） |
| 単一指標の達成度・進捗 | プログレスバーまたはゲージ型 |

### 共通ルール
- **データが5件未満の場合はグラフを表示しない**
  → 「データが5件蓄積後にグラフが表示されます（現在X件）」を表示
- グラフ色は固定：**売上=ゴールド、手数料=レッド、純利益=グリーン**
- **ツールチップ必須**：ホバー時に数値を表示する
- グラフエリアの最大高さ：320px
- 凡例アイコン：12px正方形、ラベル：13px以上

### 禁止事項
- データの性質に合わないグラフの使用
- 5件未満でのグラフ表示
- 凡例なしのグラフ表示

## ③ 入力UIの哲学：「機能は高く・操作は軽く」

### 原則
裏側でどれだけ複雑な計算や処理が走っていても、ユーザーが触れる部分は「見やすく・わかりやすく・使いやすい」に絞る。高性能であることをUIで主張しない。結果が高性能であることで証明する。

### 具体的判断基準
- 入力は**直打ち（テキスト入力）が基本**
- 単位（$・¥・%）は入力欄の外に固定テキストで表示
- 各機能セクションは独立して動作する（他のセクションの入力状態に引きずられない）
- 入力→結果の反映は**リアルタイム**または明確なアクションボタン1つで完結
- 操作ステップは最小化する

### 禁止事項
- **＋／－ボタンによる数値入力（全廃）**
- 複数ステップが必要なモーダルや確認画面の多用
- ユーザーに選択肢を多く提示しすぎること

## ④ 色・強調の哲学：「eBayの延長として機能する」

### テーマ設定（確定）
- **デフォルト：ライトテーマ**（白ベース × ゴールドアクセント）
- ダークテーマ：切り替えで提供（ネイビー × ゴールド）

### 色の使い方基準
| 用途 | 色 |
|---|---|
| 強調・アクション・重要数値 | オレンジ系（ブランドカラー） |
| ポジティブ値・達成 | グリーン系 |
| ネガティブ値・警告 | レッド系 |
| 中立・補足情報 | グレー系 |
| 背景 | 白またはごく薄いグレー（eBayに近いトーン） |

- 1画面に強調色は最大2〜3箇所に限定
- 数値の大小は色より「サイズ」で表現することを優先
- アイコンは必要な場合のみ使用し、装飾目的では使わない

### 禁止事項
- eBayと大きくかけ離れた原色の多用
- 意味のない装飾目的の色使用
- 同じ画面内での4色以上の強調色

## ⑤ 空・未完了状態の哲学：「0は0と表示する」

### 具体的ルール
- 手入力可能な欄のゼロ値 → 灰色テキストで「0」または「$0.00」
- 自動計算の未入力欄 → 「—」（横棒）で表示
- グラフデータ不足（5件未満） → グラフ非表示＋件数メッセージ表示
- ページ未実装・初期化中 → **技術的文言は表示しない**。骨格（見出し・セクション枠）を先に表示

### 禁止事項
- 「null」「undefined」「初期化中...」等の技術的文言をユーザーに見せること
- データ不足でセクションごと消えること
- 空白の大きなエリアをそのままにすること

## ⑦ レイアウト軸の哲学：「左起点・右余白」

### 原則
すべてのページのメインコンテンツは左起点とする。コンテンツブロックをページ中央に浮かせない。左側に固定の起点を持ち、右に自然な余白が生まれる状態が正しい。

### 実装ルール
- `.panel` は `padding: 28px 40px`（固定値）
- `.panel` に `max-width: 1080px` を設定し margin-auto は使わない
- `justify-content: flex-start` を基本とする

### 禁止事項
- `margin: 0 auto` でコンテンツを中央に浮かせること
- 両側に equal な可変 padding でコンテンツを中央寄せすること

## ⑧ カラム高さバランスの哲学：「量が違うことは問題ではない」

### 原則
左右2カラムで左が短くなる場合でも無理にコンテンツを追加して埋めない。空白は「余白」として自然に扱う。コンテンツの量が左右で異なることは問題ではない。

### 禁止事項
- 余白を埋めるために意味のないコンテンツを追加すること
- `align-items: stretch` でカードを強制的に同じ高さにすること（`align-items: start` を使う）

## ⑨ 動的ステータス表示の哲学：「状態が変われば見た目が変わる」

### 原則
接続状態・ステータスを示すボタンや表示は状態に応じて色・ラベルを変える動的デザインにする。

### 状態別スタイル（確定）
| 状態 | スタイル | ラベル例 |
|---|---|---|
| 未接続 | btn-primary（オレンジ） | 「接続する」 |
| 接続済み | グレーテキスト表示（非ボタン） | 「接続済み ✓」 |
| エラー | btn-danger（赤） | 「再接続」 |

### 禁止事項
- 状態が変わっても同じ色・同じデザインのままにすること

## ⑩ ボタン設計の哲学：「見た目が行動を誘導する」

### 原則
ボタンは「重要度・目的・危険度」によって見た目を必ず変える。同じ画面に同じデザインのボタンが並ぶことでユーザーはどれを押すべきか迷う。

### ボタン4階層（確定）

| 種別 | CSSクラス | 見た目 | 用途 | 1画面の上限 |
|---|---|---|---|---|
| Primary | `.btn-primary` | オレンジ背景・白文字 | 最も重要な1アクション | 1〜2個 |
| Secondary | `.btn-secondary` | 白背景・オレンジ枠・オレンジ文字 | 補助的な操作 | 制限なし |
| Ghost | `.btn-ghost` | 背景なし・グレー文字・枠なし | あってもなくてもよい操作 | 制限なし |
| Danger | `.btn-danger` | 白背景・赤枠・赤文字 | 削除・リセット等の不可逆操作 | 制限なし |

### 用途別分類（確定）
| ボタンラベル | 種別 |
|---|---|
| eBayを連携する / eBayで認証する | Primary |
| 品質をチェック | Primary |
| 記録を追加 | Primary |
| 定型文を保存 | Primary |
| 接続する（未接続時） | Primary |
| English をコピー | Secondary |
| 更新（為替レート等） | Secondary |
| 接続済み（表示のみ） | Secondary |
| 詳細 → / キャンセル / 後で / 閉じる | Ghost |
| リセット / 削除 | Danger（確認ダイアログ必須） |

### ラベル規則（確定）
- 必ず「動詞＋目的語」形式で書く
- 「OK」「はい」「実行」等の曖昧なラベル禁止

### 禁止事項
- 全ボタンを同じデザインにすること
- Primaryを1画面に3個以上置くこと
- 削除ボタンをPrimaryと同じ色にすること
- 確認ダイアログなしでDangerボタンを単独設置すること

## ⑪ ユーザー生成コンテンツの哲学：「カードの繰り返し」

### 原則
ユーザーが自由に追加・削除・編集できるコンテンツ（テンプレート・記録・リスト等）は「何件になっても同じカードが繰り返される」設計にする。件数に上限を設けない。1件でも100件でも同じパターンで表示される。レイアウトが件数によって崩れてはいけない。

### 実装基準
- カード1枚のデザインを完成させる
- そのカードが縦に積み重なる設計にする
- 「＋ ○○を追加」ボタンは常にリストの末尾に固定表示する
- 削除・編集ボタンは各カードに必ず持たせる
- カードの幅は親コンテナに従う（件数で変わらない）

### 保存の原則
- ユーザーが編集・追加したデータはSupabaseに自動保存またはボタン1つで保存する
- 保存成功時は「保存しました」トースト通知を3秒表示する
- 初期値（デフォルト）は初回起動時のみ自動セットし、以降はユーザーデータを優先する

### 禁止事項
- 件数上限を設けること
- 件数によってカードのデザインやレイアウトが変わること
- 保存ボタンがあるのに保存後の確認通知がないこと

## ⑫ カード・コンテナの統一原則

### 原則
同じ階層・同じ役割のカードは
見た目を完全に統一する。
1枚だけ背景色・サイズ・スタイルが
異なることは絶対に許容しない。

### 確定ルール
- KPIカード・サマリーカードは全て白背景（#ffffff）
- 強調は背景色ではなく「数値のサイズ・色」で行う
- 同一画面内のカードは高さ・padding・border-radiusを統一する

### 禁止事項
- 同じ役割のカードで1枚だけ背景色を変えること
- 重要度を背景色で表現すること

## ⑬ 空状態・未入力値の表示統一

### 確定ルール
- 自動計算・未入力の値：「—」（横棒1本・全角）
- 「--」「---」「…」等の表記は全て禁止
- 空のカード・セクションには必ずプレースホルダーを表示する
  → 項目名をグレーテキストで並べ、右に「—」を表示
  → 入力・データ取得後に実際の値に切り替わる
- 空状態のガイドテキストは縦横中央揃えに配置する

### 禁止事項
- 空白のままカードを放置すること
- 「---」など複数の記号で未入力を表現すること

## ⑭ オンボーディングツアーの表示方式（2026-05-29 改訂）

### 原則
初回ログイン時は「プロダクトツアー」形式で実装する。
画面を暗くしてUI要素を順番にハイライトするガイド付きウォークスルーを採用する。

### 確定ルール
- 背景を `rgba(0,0,0,0.76)` の4パネルフレームで暗くする（スポットライト方式）
- 対象UI要素をゴールドボーダーでハイライト
- 吹き出しカードを対象要素の横に表示（right/bottom/top/left の4方向指定）
- 「次へ」「戻る」「スキップ」「さっそく使う」ボタンで操作
- ドットインジケーターで進捗を表示（ステップ数分）
- localStorage `ba_tour_done` が設定されていると非表示（1回のみ表示）
- `BA.tour.reset()` でリセット可能（開発・デバッグ用）

### 実装
- `js/ui/tour.js`（`window.BA.tour`）
- スポットライト：4パネルフレーム方式（要素のz-indexを変更しない）
- ベースz-index：9000番台

### 禁止事項
- ツアー以外の説明コンテンツをオーバーレイで表示すること
- 「さっそく使う」完了後にツアーを再表示すること

## ⑮ 左右パネルのバランス原則

### 原則
左右2カラムレイアウトでは
各パネルの内容量に応じた適切な幅比率を設定する。
コンテンツが少ないパネルを
不必要に狭くしない。

### 確定ルール
- 左右パネルの比率：原則 40:60 または 50:50
- 左パネル内のボタン・要素が窮屈に見える場合は
  左パネルの幅を広げる（最小幅 280px）
- パネル内の行は上下padding 12px以上を確保する

### 禁止事項
- パネル内の要素が詰まって見える幅設定
- コンテンツに対して極端に狭いパネル幅

## ⑯ デザイントークン仕様（確定・2026-06-09）

> **全ての実装でこの一覧を参照すること。ここにないhex・px直書きは禁止。**

### テキストカラー階層（4段）

| トークン | ダーク値 | ライトmain値 | ライトsidebar値 | 用途 |
|---|---|---|---|---|
| `--text-primary` | `#e4e4e4` | `#191919` | `#e4e4e4` | 本文・数値・見出し |
| `--text-secondary` | `#b8b8b8` | `#555555` | `#c8b4a0` | サブラベル・補足情報 |
| `--text-muted` | `#9a9a9a` | `#606060` | `#8a7a6a` | 注記・補足テキスト |
| `--text-faint` | `#6e6e6e` | `#888888` | `#6a5a4a` | **プレースホルダー専用** |

**ルール：**
- ラベル類は `--text-muted` 以上の明るさを使う
- プレースホルダーのみ `--text-faint`。それ以外には使わない
- hex直書き禁止。必ずトークン経由
- 各テーマ・スコープで値が異なるのは仕様（統一しない）

### 間隔トークン（8px基準・これ以外の値は新設しない）

| トークン | 値 | 主な用途 |
|---|---|---|
| `--space-1` | 4px | 最小余白（アイコン隣接等） |
| `--space-2` | 8px | 基本単位（行内gap等） |
| `--space-3` | 12px | グリッドgap・行padding |
| `--space-4` | 16px | カードpadding縦 |
| `--space-5` | 20px | カードpadding横 |
| `--space-6` | 24px | セクション間余白 |

### 角丸トークン

# ㉑ v2.0 デザイン精緻化（2026-07-18 参考SaaS基準・以降の全UI実装で最優先）

> 参考基準：プロSaaS（Attio型CRM／計器型ダッシュボード）から抽出。
> 既存テーマ（ダーク×ゴールド/オレンジ・eBayセラー向け）は変更しない。
> 本節は既存節と矛盾する場合、本節を優先する。

## A. レイアウト：「カードは内容で決まり、グリッドで並ぶ」（横伸び禁止の恒久化）

- 画面は12カラムグリッドで設計する。カードの幅は「span数」で決め、内容量に応じて 3/4/6/8 span を選ぶ
- **1枚のカードを画面幅いっぱいに横伸びさせて空白を埋めることを全面禁止**
- カードの最大幅：フォーム系 480px / KPI系 320px / テーブル・リスト系のみ 8span まで
- 右側に余白が生まれる場合は「余白のまま」にするか、関連カードを横に並べて埋める（無理に伸ばさない）
- カード内の入力欄は①空間の哲学の幅基準を厳守（数値80-100px・金額100-120px）。カードが広くても入力欄は広げない
- 新パネル実装時は必ず「カード配置図（何spanを何枚、どの順）」を先に決めてから実装する

## B. タイポグラフィ：「サイズでなくウェイトと色で階層を作る」

- 本文基準を 13px に統一（現14px→13px）。タイプスケールを以下に改定：
  | 用途 | サイズ | ウェイト | 色 |
  |---|---|---|---|
  | ページタイトル | 20px | 600 | --text-primary |
  | セクション/カード見出し | 13px | 600 | --text-primary |
  | カードラベル（項目名） | 11px | 500・letter-spacing 0.04em | --text-muted |
  | 本文・入力値 | 13px | 400 | --text-primary |
  | 主要数値（KPI） | 24px | 600・tabular-nums | --text-primary または semantic色 |
  | 補足・注釈 | 11px | 400 | --text-faint |
- **数値は全て font-variant-numeric: tabular-nums 必須**（既存ルールの全域拡大）
- **ラベルのオレンジ色使用を廃止**。項目ラベルは --text-muted のグレー。オレンジは「操作可能要素・アクティブ状態・最重要1数値」のみ
- 見出しの文字サイズ差でなく、ウェイト(600)と色で階層を表現する

## C. 改行・折返し：「1〜2文字だけの改行を構造的に根絶」

- ラベル・見出し・ボタン文言：white-space: nowrap を原則付与。収まらない場合は文言を短くするか幅を1段階上げる
- 説明文・複数行テキスト：text-wrap: balance を付与（行末の孤立文字を自動防止）
- 数値+単位（¥1,500 / 25% / 30日）は必ず1行に収める（span で nowrap）
- 実装後、黒は claude-in-chrome（利用可能な場合）または Playwright-mcp のスクショで全カードの折返しを目視確認し、1〜2文字改行が1件でもあれば修正してから完了宣言する（⚡ルールに追加）

## D. 色の再配分：「オレンジの総量を減らし、目の疲れを消す」

- 1画面のオレンジ適用箇所を最大5箇所までに制限（btn-primary、アクティブnav、最重要数値1つ、リンク/操作要素）
- サーフェス階層を3段で統一：
  --surface-0（ページ背景）/ --surface-1（カード）/ --surface-2（カード内のネスト要素・入力欄）
  各カードは surface-1 + 1px の --border。影(box-shadow)による立体表現は使わない
- ステータス表現はテキスト色でなく「ピル型チップ」（11px・角丸999px・背景=semantic色の12%透過・文字=semantic色）に統一
  例：良好=グリーンチップ / 警告=イエローチップ / 不合格=レッドチップ / フォールバック=グレーチップ
- semantic色（green/red/yellow）はデータの意味がある箇所のみ。装飾に使わない

## E. 密度：「行間を詰め、情報密度をプロ水準に」

- カードpadding：16px（現20px相当から縮小・--space-4に統一）
- カード内の行間gap：8px（--space-2）、セクション間：16px（--space-4）
- テーブル/リスト行の高さ：36px基準・上下padding 8px
- アイコンは14px・ラベルの左に4px gapで添える（参考画像のicon+labelパターン）。装飾目的の使用は引き続き禁止

## F. 検証プロセス（黒の自己完結ルール・⚡ルールに追加・2026-07-19改訂）

- UI変更後、黒は claude-in-chrome（利用可能な場合）または Playwright-mcp で該当パネルのスクショを撮り、以下を自己チェックしてから完了宣言する：
  1. 横伸びカードがないか（A基準）
  2. 1〜2文字改行がないか（C基準）
  3. オレンジが5箇所以内か（D基準）
  4. 数値が tabular-nums か（B基準）
- ローカル開発サーバーでの確認は Playwright-mcp を優先。外部サービス（GitHub等）のログインセッションが必要な確認のみ claude-in-chrome を使う（グローバルCLAUDE.mdのツール優先順位と統一）
- スクショはオーナーへの共有用として screenshots/ に保存し、完了報告に添付する。あわせて使用したツール（claude-in-chrome / Playwright-mcp）を完了報告に明記する
