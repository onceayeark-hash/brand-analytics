# BRAND ANALYTICS｜UI設計哲学書 v1.1
> 新しい画面・要素を実装する際は必ずこれを参照すること
> **哲学書は「実態の記録」。実装と食い違う場合は実装を優先し、哲学書を更新する。**

## このツールの本質
使用者はeBayセラーであり、すでにMy eBayの画面に慣れ親しんでいる。このツールはMy eBayの延長線上にあるべきであり、見慣れた安心感を保ちながら、My eBayにはない高機能を提供することが目的である。
**「高性能だが重くない・シンプルだが頼れる」がすべての判断の基準軸。**

## ① 空間・余白の哲学：「内容に従う」

### 原則
入力欄・表示枠のサイズは「中に入るコンテンツ」に従って決める。枠が内容を支配するのではなく、内容が枠のサイズを決める。

### コンテンツ別サイズ基準
| コンテンツ種別 | 入力欄幅 |
|---|---|
| 数値・パーセント・手数料率（5文字前後） | 80〜100px |
| 金額（$・¥）（最大7〜8文字） | 100〜120px |
| 商品名・タイトル（最大80文字以上） | 100%（横幅いっぱい） |
| ラベル・補足テキスト | 内容の長さに合わせる |

### テキスト配置の原則
- 文字・商品名・ラベル・説明文 → **左詰め**
- 金額・数値・パーセント → **右詰め**（桁が縦に揃い、比較が容易）
- ボタン内テキスト → **中央揃え**
- テーブルヘッダー → 列の内容に合わせる（数値列=右揃え、文字列=左揃え）
- 100%幅は商品名・タイトル入力欄のみ。数値・金額・パーセント入力欄には適用しない。

### 禁止事項
- 全要素を同じ幅に揃えること（内容無視の統一）
- 数値入力欄を不必要に横長にすること
- コンテンツが少ないのにカードを大きく取ること
- 数値を左詰めにすること

## ② データ表示の哲学：「データの性質でグラフを選ぶ」

### 原則
グラフの種類は「何を伝えたいか」で決まる。見た目の好みではなく、データの性質に最適なグラフを選ぶことが読み手への誠実さである。

### グラフ選択の判断基準
| データの性質 | グラフ種類 |
|---|---|
| 時系列の推移（月ごとの売上等） | 縦棒グラフ（別軸指標は折れ線で重ねる） |
| 構成比・シェアの比較 | 円グラフ（ドーナツ型推奨・最大8項目） |
| 2指標の対比（売上vs手数料等） | 並列縦棒グラフ（グループ棒グラフ） |
| 単一指標の達成度・進捗 | プログレスバーまたはゲージ型 |

### 共通ルール
- **データが5件未満の場合はグラフを表示しない**
  → 「データが5件蓄積後にグラフが表示されます（現在X件）」を表示
- グラフ色は固定：**売上=ゴールド、手数料=レッド、純利益=グリーン**
- **ツールチップ必須**：ホバー時に数値を表示する
- グラフエリアの最大高さ：320px
- 凡例アイコン：12px正方形、ラベル：13px以上

### 禁止事項
- データの性質に合わないグラフの使用
- 5件未満でのグラフ表示
- 凡例なしのグラフ表示

## ③ 入力UIの哲学：「機能は高く・操作は軽く」

### 原則
裏側でどれだけ複雑な計算や処理が走っていても、ユーザーが触れる部分は「見やすく・わかりやすく・使いやすい」に絞る。高性能であることをUIで主張しない。結果が高性能であることで証明する。

### 具体的判断基準
- 入力は**直打ち（テキスト入力）が基本**
- 単位（$・¥・%）は入力欄の外に固定テキストで表示
- 各機能セクションは独立して動作する（他のセクションの入力状態に引きずられない）
- 入力→結果の反映は**リアルタイム**または明確なアクションボタン1つで完結
- 操作ステップは最小化する

### 禁止事項
- **＋／－ボタンによる数値入力（全廃）**
- 複数ステップが必要なモーダルや確認画面の多用
- ユーザーに選択肢を多く提示しすぎること

## ④ 色・強調の哲学：「eBayの延長として機能する」

### テーマ設定（確定）
- **デフォルト：ライトテーマ**（白ベース × ゴールドアクセント）
- ダークテーマ：切り替えで提供（ネイビー × ゴールド）

### 色の使い方基準
| 用途 | 色 |
|---|---|
| 強調・アクション・重要数値 | オレンジ系（ブランドカラー） |
| ポジティブ値・達成 | グリーン系 |
| ネガティブ値・警告 | レッド系 |
| 中立・補足情報 | グレー系 |
| 背景 | 白またはごく薄いグレー（eBayに近いトーン） |

- 1画面に強調色は最大2〜3箇所に限定
- 数値の大小は色より「サイズ」で表現することを優先
- アイコンは必要な場合のみ使用し、装飾目的では使わない

### 禁止事項
- eBayと大きくかけ離れた原色の多用
- 意味のない装飾目的の色使用
- 同じ画面内での4色以上の強調色

## ⑤ 空・未完了状態の哲学：「0は0と表示する」

### 具体的ルール
- 手入力可能な欄のゼロ値 → 灰色テキストで「0」または「$0.00」
- 自動計算の未入力欄 → 「—」（横棒）で表示
- グラフデータ不足（5件未満） → グラフ非表示＋件数メッセージ表示
- ページ未実装・初期化中 → **技術的文言は表示しない**。骨格（見出し・セクション枠）を先に表示

### 禁止事項
- 「null」「undefined」「初期化中...」等の技術的文言をユーザーに見せること
- データ不足でセクションごと消えること
- 空白の大きなエリアをそのままにすること

## ⑦ レイアウト軸の哲学：「左起点・右余白」

### 原則
すべてのページのメインコンテンツは左起点とする。コンテンツブロックをページ中央に浮かせない。左側に固定の起点を持ち、右に自然な余白が生まれる状態が正しい。

### 実装ルール
- `.panel` は `padding: 28px 40px`（固定値）
- `.panel` に `max-width: 1080px` を設定し margin-auto は使わない
- `justify-content: flex-start` を基本とする

### 禁止事項
- `margin: 0 auto` でコンテンツを中央に浮かせること
- 両側に equal な可変 padding でコンテンツを中央寄せすること

---

## ⑧ カラム高さバランスの哲学：「量が違うことは問題ではない」

### 原則
左右2カラムで左が短くなる場合でも無理にコンテンツを追加して埋めない。空白は「余白」として自然に扱う。コンテンツの量が左右で異なることは問題ではない。

### 禁止事項
- 余白を埋めるために意味のないコンテンツを追加すること
- `align-items: stretch` でカードを強制的に同じ高さにすること（`align-items: start` を使う）

---

## ⑨ 動的ステータス表示の哲学：「状態が変われば見た目が変わる」

### 原則
接続状態・ステータスを示すボタンや表示は状態に応じて色・ラベルを変える動的デザインにする。

### 状態別スタイル（確定）
| 状態 | スタイル | ラベル例 |
|---|---|---|
| 未接続 | btn-primary（オレンジ） | 「接続する」 |
| 接続済み | グレーテキスト表示（非ボタン） | 「接続済み ✓」 |
| エラー | btn-danger（赤） | 「再接続」 |

### 禁止事項
- 状態が変わっても同じ色・同じデザインのままにすること

---

## ⑩ ボタン設計の哲学：「見た目が行動を誘導する」

### 原則
ボタンは「重要度・目的・危険度」によって見た目を必ず変える。同じ画面に同じデザインのボタンが並ぶことでユーザーはどれを押すべきか迷う。

### ボタン4階層（確定）

| 種別 | CSSクラス | 見た目 | 用途 | 1画面の上限 |
|---|---|---|---|---|
| Primary | `.btn-primary` | オレンジ背景・白文字 | 最も重要な1アクション | 1〜2個 |
| Secondary | `.btn-secondary` | 白背景・オレンジ枠・オレンジ文字 | 補助的な操作 | 制限なし |
| Ghost | `.btn-ghost` | 背景なし・グレー文字・枠なし | あってもなくてもよい操作 | 制限なし |
| Danger | `.btn-danger` | 白背景・赤枠・赤文字 | 削除・リセット等の不可逆操作 | 制限なし |

### 用途別分類（確定）
| ボタンラベル | 種別 |
|---|---|
| eBayを連携する / eBayで認証する | Primary |
| 品質をチェック | Primary |
| 記録を追加 | Primary |
| 定型文を保存 | Primary |
| 接続する（未接続時） | Primary |
| English をコピー | Secondary |
| 更新（為替レート等） | Secondary |
| 接続済み（表示のみ） | Secondary |
| 詳細 → / キャンセル / 後で / 閉じる | Ghost |
| リセット / 削除 | Danger（確認ダイアログ必須） |

### ラベル規則（確定）
- 必ず「動詞＋目的語」形式で書く
- 「OK」「はい」「実行」等の曖昧なラベル禁止

### 禁止事項
- 全ボタンを同じデザインにすること
- Primaryを1画面に3個以上置くこと
- 削除ボタンをPrimaryと同じ色にすること
- 確認ダイアログなしでDangerボタンを単独設置すること

## ⑪ ユーザー生成コンテンツの哲学：「カードの繰り返し」

### 原則
ユーザーが自由に追加・削除・編集できるコンテンツ（テンプレート・記録・リスト等）は「何件になっても同じカードが繰り返される」設計にする。件数に上限を設けない。1件でも100件でも同じパターンで表示される。レイアウトが件数によって崩れてはいけない。

### 実装基準
- カード1枚のデザインを完成させる
- そのカードが縦に積み重なる設計にする
- 「＋ ○○を追加」ボタンは常にリストの末尾に固定表示する
- 削除・編集ボタンは各カードに必ず持たせる
- カードの幅は親コンテナに従う（件数で変わらない）

### 保存の原則
- ユーザーが編集・追加したデータはSupabaseに自動保存またはボタン1つで保存する
- 保存成功時は「保存しました」トースト通知を3秒表示する
- 初期値（デフォルト）は初回起動時のみ自動セットし、以降はユーザーデータを優先する

### 禁止事項
- 件数上限を設けること
- 件数によってカードのデザインやレイアウトが変わること
- 保存ボタンがあるのに保存後の確認通知がないこと

## ⑫ カード・コンテナの統一原則

### 原則
同じ階層・同じ役割のカードは
見た目を完全に統一する。
1枚だけ背景色・サイズ・スタイルが
異なることは絶対に許容しない。

### 確定ルール
- KPIカード・サマリーカードは全て白背景（#ffffff）
- 強調は背景色ではなく「数値のサイズ・色」で行う
- 同一画面内のカードは高さ・padding・border-radiusを統一する

### 禁止事項
- 同じ役割のカードで1枚だけ背景色を変えること
- 重要度を背景色で表現すること

---

## ⑬ 空状態・未入力値の表示統一

### 確定ルール
- 自動計算・未入力の値：「—」（横棒1本・全角）
- 「--」「---」「…」等の表記は全て禁止
- 空のカード・セクションには必ずプレースホルダーを表示する
  → 項目名をグレーテキストで並べ、右に「—」を表示
  → 入力・データ取得後に実際の値に切り替わる
- 空状態のガイドテキストは縦横中央揃えに配置する

### 禁止事項
- 空白のままカードを放置すること
- 「---」など複数の記号で未入力を表現すること

## ⑭ チュートリアル・ガイドの表示方式

### 原則
チュートリアルは画面全体を覆うオーバーレイで
表示してはいけない。
メインコンテンツは常に見える状態を保つ。

### 確定ルール
- チュートリアルはページ上部のインラインバナーで表示
- ×ボタンで閉じられる
- 背景を暗くするオーバーレイは使用禁止
- 全ページで同一のバナースタイルに統一する

### 禁止事項
- モーダル・オーバーレイ形式のチュートリアル
- メインコンテンツが見えなくなる表示方式

## ⑮ 左右パネルのバランス原則

### 原則
左右2カラムレイアウトでは
各パネルの内容量に応じた適切な幅比率を設定する。
コンテンツが少ないパネルを
不必要に狭くしない。

### 確定ルール
- 左右パネルの比率：原則 40:60 または 50:50
- 左パネル内のボタン・要素が窮屈に見える場合は
  左パネルの幅を広げる（最小幅 280px）
- パネル内の行は上下padding 12px以上を確保する

### 禁止事項
- パネル内の要素が詰まって見える幅設定
- コンテンツに対して極端に狭いパネル幅
