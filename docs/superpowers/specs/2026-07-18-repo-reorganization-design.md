1. コードと無関係な業務素材の混在を解消し、リポジトリをコード＋MDのみのクリーンな状態にする

## B. CLAUDE.md 憲法化（67KB → 約10KB）

### CLAUDE.md に残すもの
- セッション開始手順・⚡自動発動ルール（先頭付近に配置）
- ナビゲーション確定名称・リサーチ実装方針の要点
- 障害対応プロトコル
- 仕様参照表（「○○を実装するときは `docs/specs/○○.md` を読む」）

### docs/specs/ へ機能別に切り出すもの（原文維持で転記）
- STAGE2各仕様：ベストオファー・返品コスト・自動値下げ・SpeedPAK送料計算・自動出品
- STAGE3リサーチ仕様（Terapeak CSV・DBスキーマ・パイプライン・sold取得A案含む）
- Claude API統合基盤／eBayポリシー自動監視／eBaymag連携（3重複→1本統合）
- 管理者パネル（2重複→1本統合）／健全性予測／最終利益2層設計
- トライアル管理・LINEアラート・eBay遷移最小化／Growth Check申請ノウハウ
- 実装済みUI仕様（費用内訳カード・設定ページ）→ `context/specs.md` に吸収

### @import の絞り込み
- 維持：`context/skills.md`・`context/specs.md`・`context/architecture.md`・`context/coding-rules.md`
- 自動読込から除外：`context/design-philosophy.md` → ⚡ルールに「UI実装・変更時は必ず読む」行を明記しオンデマンド化

### 取捨ルール
- 転記は原文維持。勝手な要約・改変はしない
- 完全重複のみ最新版に統合
- 古い【UI修正依頼①②】は対応済みか確認の上、済なら除去

## C. 承認時追加条件（2026-07-18）

1. **履歴再確認**：`APIキー　パスワード.docx` の移動前に `git log --all -- "APIキー*"` で追跡履歴ゼロを再確認（履歴があれば移動前に報告・相談）→ **実施済み・履歴ゼロ確認済み**
2. **1コミット確定**：git rm --cached を含むため、整理完了時に1コミットとして確定させる。コミット実行は完了報告→ユーザー承認後
3. **参照表の実地テスト**：整理完了後の新セッションでUI変更タスクを1件実行し、`design-philosophy.md` をオンデマンドで読みに行くことを確認する

## D. 検証方法

1. 新CLAUDE.mdの仕様参照表のパスが全て実在すること
2. `npm run check:security` が通ること（`context/skills.md` は無変更のため影響なしの見込み）
3. 移動前後のファイル数突き合わせで消失ゼロを確認
4. コミットは完了報告→承認後に1コミットで実行
5. （後続・新セッション）参照表の実地テスト＝条件3
