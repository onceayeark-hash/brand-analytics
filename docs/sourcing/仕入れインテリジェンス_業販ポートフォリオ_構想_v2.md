## 0. 基本方針

- **個人専用・一切販売しない。** 理由：自分の資金柱が立つ前に、競合を利するツールを渡さない。
- **対象は BtoB 業者オークション限定**（古物商の世界）。国内フリマ（メルカリ等）は対象外＝古物商の論点を回避。
- **取得は必ず人間（オーナー）が行う。** オークション開催時のURL／ページ内容はオーナーが取得して渡す。
  ツールが自動巡回・自動入札はしない（会場規約・会員資格リスクを残さない＝仕入れの生命線を守る）。
- AI（Claude API）の役割は「**読む・計算する・並べる・提案する**」。最終判断・入札はオーナー。

## 1. 事業戦略：BtoC × BtoB ポートフォリオ

リユース・ハイブランドの2販路を**逆相関で組み合わせ**、売上とキャッシュフローの凹凸をなくす。

| 販路 | 粗利 | 回転 | 流動性／予測 | 性質 |
|---|---|---|---|---|
| BtoC（eBay小売） | 約25% | 遅い・販売日が読めない | 低流動・予測困難 | 高利益／資金が寝る |
| BtoB（業者オークション・業販／ハタ） | 約10〜15%（ポートフォリオならし値） | **約1ヶ月**※ | 高流動・ほぼ確実に成約／着金予測可 | 薄利／現金が回る |

※BtoB回転の内訳（確定）：落札→2日で到着→検品・クリーニング・リペア 約7日→業販出品〜成約 約14日→着金は成約2日後＝**合計 約1ヶ月**。

**戦略の核**：BtoBで資金を高速・確実に回して現金を生み、その現金でBtoCの高粗利・寝かせ在庫を回す。
BtoCの「資金が寝る」弱点を、BtoBの「予測可能な1ヶ月回転＋ほぼ確実な成約」で埋める＝**売上・CFの平準化**。

**最大リスク**：販路拡大による資金圧迫。儲かる戦略ほど資金管理を誤ると死ぬ。
→ だから本ツール群の最重要機能は「**資金配分とキャッシュフロー予測**」。

**BtoB薄利の実態（重要）**：粗利10〜15%は複数商品のポートフォリオでならした結果値。
個別商品では¥100,000想定でハタしても実際は¥89,000成約など、**想定を下回る（赤字）**ことが多々ある。
薄利ゆえの特性であり、これは勝率の問題ではなく「個別の下振れをポートフォリオで吸収する」設計思想。
→ **管理すべきは「個別商品の勝率」ではなく「ポートフォリオ全体の実質利益率」**。

**利益の源泉は2つの"歪み（アービトラージ）"**
- ① 為替アービトラージ（BtoC）：円安＋ドル高＋日本人セラーへの安心感で、国内低ランクでも海外で値がつく。
- ② 会場間 評価ミスマッチ（BtoB）：同じ商品が会場によって違う評価・値段になる歪みを突く。

## 2. 販路別 勝ち筋マトリクス（オーナーの暗黙知）

### BtoC（eBay限定。国内フリマは卒業）
- ブランド：ハイブランド固定（ヴィトン／グッチ／シャネル／プラダ／サンローラン／バレンシアガ。売上メインはほぼこれ）。
  ※「幅広く」と思いきや、**売れ筋はほぼ固定**。
- ランク：**B〜BC（低品質）が最適**。仕入れと販売の回転が最もマッチ。
- 理由：
  1. 円安＋日本人セラーから安く良い物を買いたい海外勢が多い。
  2. ドル高で、国内では低ランクでも海外では為替差で値がつく。
  3. A〜AB（高ランク）は国内大手小売・店舗事業者が狙う→競合厚→値幅の乖離が生まれにくい。
- ＝**「低ランクの為替アービトラージ」**が本質。

### BtoB（業販・ハタ）
- ブランド：エルメス／ヴィトン／ディオール 等、中〜高単価。
- ランク：AB〜BC、仕入れ値 約¥80,000〜¥500,000。
  ※ある程度の仕入れ値がないと、薄利ゆえ効率が落ち利益が薄くなる。
- 狙い方①（場所のミスマッチ）：オークネット等の大規模（低単価転売・海外勢が多い）で、
  国内向け筋商品（例：ラムスキンのマトラッセ）が**手薄→安く仕入れ**→（時にクリーニング／高度リペア）→
  高品質高単価がウリのスターバイヤーズ／ペンギントレードへ流す（ハタ）→メイン事業者に掴ませて利幅。
- 狙い方②（評価軸のミスマッチ）：高品質特化のスターバイヤーズで、筋商品だが品質がど真ん中でない（B〜BC）ため
  **軽視され安い→お買い得で仕入れ**→（リペア or そのまま）→ペンギントレードへ。

## 3. コア機能：最適出し先ルーティング ＋ 価格差逆算

本ツールの価値は「相場を見る」ことではなく、
**「この商品×このランクは、どの販路／会場に出すのが最適か」をオーナーの知見で提案すること**。

### 主軸：価格差ドリブン（粗利率を固定の前提に置かない）

> 固定の粗利率でフィルタするのではなく、**価格差の絶対値** から逆算して判断する。
> 目標粗利率でのフィルタは可能だが主軸ではない。

#### 価格差逆算フロー
```
① オーナーが「狙い商品」を登録する
   商品名（例：マトラッセ W/Cチェーン ラムスキン B）＋ 想定販売額（¥）

② ツールがオークション情報（オーナー提供）を読む
   仕入れ値候補（落札予想 or 現在価格）を把握

③ 価格差・粗利額を逆算
   粗利額（¥）= 想定売値 − 仕入れ値 − 手数料合計 − リペアコスト
   ※仕入れ会場手数料・販売会場成約手数料・eBay各手数料の解読は既存ロジックで処理。構想には細かく書かない。

④ 乖離が大きい商品・オークションを上位に表示
   主軸①：粗利額（絶対値、¥）
   主軸②：価格差の乖離（仕入れ値 vs 想定売値の差が大きい順）
   参考指標：粗利率（%）
   ※年換算ROIは主軸から外す。
     理由：eBay側での回転日数を正確に分析できないため、主軸に置くと判断を誤る。
```

#### 入出力
```
入力：ブランド × 商品（筋か）× ランク × 仕入れ値 × 仕入れ会場 × 痛み（注意事項）× 写真

出力：
 - 推奨販路：eBay(BtoC) / どの業販会場(ハタ先) か
 - 理由：「為替アービトラージ向き」「会場ミスマッチ向き」等
 - 想定売値・適正指値・指値限度
 - 粗利額（主）・粗利率（参考）・価格差乖離スコア（主）
 - 付加工程の判断：そのまま / 簡易クリーニング / 高度リペア＋費用対効果
```

## 4. 判断エンジン（写真 ＋ 注意事項 ＋ ルール法則）

### 4-1. 入力の2系統
- **写真**：商品画像（複数枚）。痛みの一次スクリーニング。
- **注意事項テキスト**：会場記載の構造化された痛み情報（例：「全体擦れ(中)/角擦れ(中)/ヌメ革やけ汚れ(中)/ヌメ革ヒビ(小)/金具キズ(中)/内側汚れ(中)」）。

### 4-2. 役割分担（AI ／ 人間）
| 工程 | AI | オーナー |
|---|---|---|
| 注意事項の構造化（痛みの種類・程度） | ◎ 正確 | — |
| 写真からの痛み検出（一次スクリーニング） | ○ 補助 | 最終判定 |
| リペア可否判定（補色可／破れ不可） | ◎ ルール適用で強い | ルール提供 |
| ランク微差（B vs BC の境目）・真贋 | △ 補助のみ | **主体** |
| 価格差計算・指値逆算 | ◎ 既存ロジックで処理 | 確認 |

### 4-3. リペア変換ルール（俗人知の核）
- 色あせ／角スレ／コバはがけ等は、**特定素材なら補色（リペア）で品質アップ可能**→ランクが化ける。
- 破れ・切れは**リペア困難**→スルー or そのままハタで転売戦略。
- ＝「**痛み → リペア可否 → 出し先 → 粗利額**」の変換ルールが、利益の分岐点。

## 5. ナレッジDB ＝ 法則体系（"学習"の正体）

### 5-1. 重要な技術的前提（誤解防止）
- **Claude（AI）自身は会話をまたいで学習・記憶しない。** 賢くなるのは「AIの脳」ではなく、
  **オーナーが構築する"ナレッジDB（判断法則の体系）"**。AIはそのDBを毎回参照して判断する**実行役**。
- これにより、知見は**消えず・漏れず・オーナーの所有物**になる＝堀として理想的。

### 5-2. 分離方針（確定）
- ナレッジDB・ツール全体は **ブランドアナリティクス本体と完全分離**する（個人ツールとして独立・安全を優先）。
- Supabaseプロジェクト・GitHubリポジトリともに分離前提で設計する。
- ※閉ループ連携（仕入れ実績 × eBay販売実績の答え合わせ）は、分離前提でも後から設計可能。実装着手時に設計する。

### 5-3. リユースは一点物 → 「事例マッチング」でなく「ルール・法則」を貯める
- リユース品は世界に一つ＝同一商品の正解データが無い。単純な事例マッチングは効かない。
- 効くのは**要素（痛みの種類・素材・ランク・会場・ブランド型番）の組み合わせに対する"法則"**。
  一点物でも要素は共通だから、法則は使い回せる。

### 5-4. ナレッジDBに貯める法則の例
- 素材ルール：ラムスキン × 角擦れ(中) → 補色可 → AB へ化ける。
- 会場ルール（ランク変換表）：エコリングの B ≒ オークネットの C。
  ※会場社員が目視・アナログで決めるため基準がバラバラ＝この差こそ「評価ミスマッチ」の利益源。
- ブランド型番ルール：例 M41534 ミニスピーディは、付属品より本体ヌメ革の状態が価格を決める。
- 除外ルール：破れ・切れ＝リペア不可 → そのままハタ or スルー。
- 出し先ルール：筋商品 × 低評価会場で安値 → 高評価会場（ペンギン等）へ。

### 5-5. 学習ループ
```
オーナーが事例を送る（写真＋注意事項＋自分の判定＋落札/販売結果）
   ↓
ツールが「判断ルール・法則」としてナレッジDBに蓄積
   ↓
新しい個体（一点物）が来たら、ツールが該当法則をAPIに一緒に渡す
   ↓
AIがオーナーの法則を全部通して判断・指値・出し先を提案
   ↓
結果をDBに追記 → 法則を補正・追加 → 精度が上がる
```

### 5-6. ゴールは「超人目利き」ではなく「ブレの除去・再現性」
- 人間の名人も体調・気分・見落としで判断がブレる。
- 法則化すれば、同じ条件には常に同じ判断＝**ブレが消え、名人の平均点を安定して出す**。
- **精度が粗い初期**：法則数が少ないためAI提案の信頼度は低い。法則数が増えるほど育つ。「最初から全自動の目利き」にはならない。

## 6. 対象会場プロファイル（社ごとの差を吸収）

各業販会社で UI・入札／記帳ルール・手数料・ランク定義・URL構造が異なる（文脈は共通：写真＋注意事項＋要点文言）。
→ 会場ごとに「プロファイル」を登録し差を吸収する。

プロファイルに含む情報：
- 手数料・落札料・成約料
- ランク定義と会場間変換表（例：エコリング B ≒ オークネット C）
- URL構造（開催・商品ページ）
- 入札単位・記帳ルール
- 会場の傾向（低単価転売／海外勢が多い 等）

→ 会場一覧は **付録A** 参照。

## 7. UI方針

### 起動時のメイン動線
```
起動
  ↓
[ BtoC ] / [ BtoB ] タブで販路を選択
  ↓
保存した「狙い商品リスト」が表示される
  商品名 / 参考画像（任意）/ 想定売値 / 想定指値上限
  ↓
オークション情報（オーナーが取得して貼り付け or 入力）を渡す
  ↓
価格差・粗利額を逆算 → 乖離が大きい順にターゲット提示
  ↓
ナレッジDB法則を適用 → 推奨ハタ先・最適指値・リペア判定
```

### 狙い商品リストの登録
- 商品名 + 参考画像（任意）+ 想定売値（BtoC：eBay予想額 / BtoB：ハタ先予想額）
- いつでも追加・編集・削除可能
- これが「仕入れリサーチの起点」。狙い商品がない状態では判断精度が出ない。

### 会場横断UI統一の価値（即時効果）
各業者オークションのサイトはそれぞれ見づらく・使いづらい。
本ツールで**全会場を1つの統一UIに集約**することで、サイトをまたいだ比較が一画面で完結する。

- データ蓄積を待たずに**初日から業務効率化の効果**が出る
- 各会場のバラバラなデザイン・操作感を統一された美しいUIに変換
- 複数会場を行き来する手間がゼロになる

## 7-B. データ蓄積フライホイール戦略

### 基本思想：コードより先にデータを貯める
> **コードは後からいくらでも書ける。データだけは今日から貯め始めないと永遠に手に入らない。**

各業者オークションは古い相場データから順に消えていく（eBayと同じ仕組み）。
ツールが取り込んで蓄積したデータは消えない。時間をかけるほど**自分だけが持つ過去相場DB**が育つ。

### 毎週自動取り込みのリズム（確定）
```
毎週決まった曜日・時間にPlaywrightが自動実行
  ↓
選定会場（オークネット・ecoauc 等）から指定ブランドの出品データを取得
  ↓
Claudeが分析・過去データと比較
  ↓
Supabaseに蓄積（既存データに上書きせず追記）
  ↓
翌朝オーナーが確認・当週の仕入れ判断
```

### 手数料込み実コスト比較ランキング
各会場で手数料が異なるため、**落札価格だけでは比較にならない**。

```
オークネット 落札¥100,000 + 手数料5.5% = 実コスト ¥105,500
ecoauc      落札¥ 98,000 + 手数料8.0% = 実コスト ¥105,840

→ 表面上安いecoaucが実は高い、が一目でわかる
→ 手数料込みの実コストで自動ランキング生成
```

会場プロファイルに手数料を登録するだけで、全商品の比較が自動で正規化される。

### データ蓄積で生まれる判断材料（時間軸）

| 蓄積期間 | 使える判断 |
|---|---|
| 1ヶ月 | 「先月より相場が上がっている」の根拠 |
| 3ヶ月 | 季節変動パターンの把握 |
| 6ヶ月 | 「このブランドはこの時期に安くなる」の検証 |
| 1年〜 | 仕入れタイミング最適化・AIによる週次推奨候補 |

### データさえあれば選択肢が最大化する
蓄積データをベースに**後からいくらでも機能を追加できる**：
- 相場予測（過去トレンドから算出）
- 会場間ミスマッチの自動検知（同一商品が会場によって安い/高い）
- リペア投資の費用対効果を実績データで検証
- AIによる「今週買うべき商品TOP5」自動生成

---

### 実装前提条件：F12サイト構造解析
Playwrightで各会場を自動操作するには、**サイトごとのHTML構造の事前解析が必要**。

```
ブラウザのF12（開発者ツール）で確認する情報：
  - ログインフォームのID・name属性
  - 検索フィールドのセレクタ
  - フィルターボタンの位置・クラス名
  - 商品リストの構造（価格・ランク・商品名の取得先）
  - ページネーションの仕組み
```

オーナーがF12で確認した情報（またはスクリーンショット）を渡す
→ 黒がPlaywrightのセレクタを実装する、という分業が実装の起点になる。
**解析さえできれば、あとは確実に動くものが作れる。**

## 8. ブランドアナリティクス（本体）との連携：閉ループ（将来）

- **仕入れインテリジェンス（本書・BtoB/BtoC入口）**：何をいくらで仕入れ、どこに出すか。
- **ブランドアナリティクス（本体・BtoC出口）**：売れた後、いくらで売れていくら残ったか（Finances API実績）。
- 両者を繋ぐと：**仕入れ → 販売 → 実績 → 次の仕入れ判断** の閉ループ。
  仕入れ時の「想定売値」を販売後の実績で答え合わせ → 次の指値・法則の精度が上がる。

**分離前提での連携**：両ツールが完全分離でも、後からエクスポート/インポートまたはAPI連携で閉ループは実現可能。実装着手時に設計する。

### 連携で持つべき指標（将来）
- 販路別 資金回転率（薄利高回転 BtoB と 高利益低回転 BtoC を比較）
- キャッシュフロー予測（BtoBの着金タイムライン × BtoCの寝かせ在庫で資金の谷を事前に見る）
- 資金配分メーター（余剰金を寝かせず、BtoB/BtoCにどう振るか。資金圧迫の警告）
- ポートフォリオ実質利益率管理（個別商品の下振れ込みの全体利益率）
- 付加工程の費用対効果（補色コスト vs 落札価格の上昇）

## 9. 正直な限界・前提（隠さず明記）

- 写真判定は**一次スクリーニング止まり**。ランク微差（B vs BC）・真贋は**人間が主体**。
- AIは会話で学習しない。賢くなるのは**ナレッジDB（法則）**。最初は精度が粗く、法則を足すほど育つ。
- 最初は**オーナーが法則を手動で定義**。実績が溜まって初めてAIの提案が補強される。いきなり全自動の目利きにはならない。
- **精度移行の目安**：法則数が少ない初期は「AIはヒント・判断は人間」として使う。法則が30〜50件以上蓄積してから信頼度を引き上げる。
- 各業販サイトの規約・会員資格リスクは残る → **「URLは人間（オーナー）が渡す」設計を維持**。自動巡回・自動入札はしない。
- 入札の最終アクションは必ず人間。AIは指値提案まで。
