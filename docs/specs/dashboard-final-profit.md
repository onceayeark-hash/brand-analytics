## ダッシュボード「最終利益」2層設計（確定・2026-06-03）
*STAGE2 仕上げ後に着手。実装前にブラウザ Claude と合算・分離設計を確定すること。*

### 設計思想

「いくら売れて・何を引かれ・いくら残ったか」を 実測 と 予測 の2層で構成する。

#### 【実測層（確定実績）】
- データ源：eBay Finances API（接続済み）の実額
- 表示フロー：
  ```
  売値
  − eBay手数料（API実額）
  − Promoted/広告費（API実額）
  − 為替（入金時実レート）
  − 真贋/送料/関税（ツール保持値・自社実コスト）
  ＝ 最終手残り（確定値）
  ```
- eBay 発生コスト = API 実額 / 自社コスト（仕入原価・国内送料・真贋・関税）= ツール保持値 を合算
- 1件から正確。これが確定値。確定申告・利益確定に使う数字

#### 【予測層（学習）】
- 履歴が増えたら実測データを AI（Claude API / 学習値）で学習し
  「この商品・価格帯なら、いくら残りそうか」の精度の高い予測を出す
- 既存の学習値思想（transactions.js / P-03 / PPD予測）の発展
- 用途：意思決定の補助のみ。確定値として扱わない

### 必須ルール（実装時遵守）

1. **実測（確定）と予測（見込み）は UI で明確に分離・ラベル表示する**
   お金の確定値に予測を混ぜない
2. **確定申告・利益確定の数字は実測（Finances API 実額）のみ使用する**
   予測値を使わない
3. **学習はユーザー自身の取引データをユーザーに返す範囲に限定**
   C-07①（eBay データの AI 学習禁止）抵触回避。実装時に規約再確認
4. **eBay 発生コストと自社コストの合算ロジックを明確に定義する**
   混在させない
