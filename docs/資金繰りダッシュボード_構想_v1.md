## 0. 背景・目的

小売（eBay）は商品を先に仕入れる業態のため、資金が先に手出しになる。
無在庫と違いキャッシュフロー管理が事業の生命線。資金ショートは事業を止める最大リスク。

このダッシュボードで明確にしたいこと（3つを同格で扱う）：
1. **監視**：このままで資金ショートしないか（危険を事前に検知）
2. **逆算**：目標粗利を達成するにはいくら資金が必要か
3. **順算**：今の資金でどれだけの売上・粗利が見込めるか

対象販路：**eBay の売上・仕入れのみ**（業販/BtoBは混ぜない。将来別軸として検討）。

## 1. データ源

| データ | 取得元 | 用途 | 状態 |
|---|---|---|---|
| 手元資金・口座残高・経費・将来出費 | MF API | 出撃可能資金・安全資金・将来出費 | 要確認（着手時） |
| 販売・入金予定日・入金額（確定） | eBay Finances API | 確定入金のCF・実績 | 接続済み(X-01/T-01) |
| 成約率・平均売価・平均仕入額・回転 | 取引記録(transactions) | 将来売上予測・前提値 | 既存データ |

- 前提値（成約率・平均売価・平均仕入額等）は**すべて取引記録から自動計算（実績値）**。
  手動上書きは将来検討（まずは自動実績ベース）。
- MF API：認証はOAuth2.0またはAPIキー方式が公式提供されている（eBay OAuthと同様の仕組みで実装可能）。
  ただし「口座残高・入出金・経費」が具体的にどのエンドポイント/権限で取れるかは**着手時に要確認**。

## 2. 中核ロジック

### 2-1. 出撃可能資金（今、仕入れに回せる額）
```
出撃可能資金 = 総資金(MF) − 安全資金 − 将来出費(確保分)
  安全資金   = 経費の○ヶ月分を自動確保（○はユーザー設定）
  将来出費   = 家賃・税金・保険など「いずれ出ていくお金」
```

### 2-2. 将来出費の把握（半自動）
- MFの過去出金履歴から、定期/不定期の出費を**自動で拾って候補提示**。
- ※完全自動の分類は誤検出があるため、**「自動検出 → ユーザーが定期/無視を確認・微修正」の半自動**が現実的な落とし所
  （同額が毎月出ていれば定期と推測、等。精度はユーザー確認で担保）。

### 2-3. 将来売上予測（資金ショート予測の必須要素）
**この予測がないと「出費だけ積み上がる無意味なショート予測」になる。必須。**
```
出品中の商品数 × 実績成約率 → 予測成約点数
予測成約点数 × 平均売価/平均入金額 → 予測売上・予測入金
```
- 月次で「**予測額 vs 実額**」を比較し、**予測を改善する**（成約率・回転などの係数を実績で更新）。
  ＝データ蓄積で予測精度が上がる仕組み（AIが脳で学習するのではなく、蓄積実績から係数更新）。

### 2-4. キャッシュフロー予測
```
未来の各日 = 期首残高
  ＋ 確定入金（Finances APIの入金予定日・実線）
  ＋ 将来売上予測の入金（点線・見込み）
  − 将来出費（家賃・税金・保険等）
  − 補充仕入れ
```

## 3. 画面（ダッシュボード内 1セクション）

### 3-1. 表示の主役（優先順）
1. **CFタイムライン**（入出金の折れ線グラフ）← 最優先・一番大きく
2. **目標達成度**（目標粗利/売上/必要資金にあといくら）
3. **出撃可能資金**（今仕入れに回せる額）
4. **資金ショート警告**（危険日のアラート）

### 3-2. CFタイムライン
- **日次**・**期間可変**（ユーザーが表示期間を選べる）。
- **確定入金＝実線／将来売上予測＝点線**で明確に区別（実測と予測を混ぜない）。
- グラフ下部に**つまんで横移動できるボタン（スライダー）**、ボタン位置の**縦ライン上に具体数字**を表示。

### 3-3. 目標達成度
- **実売上・販売件数をメイン**に表示し、それを基に「粗利・売上・必要資金」を可視化。
- 基本**月ベース**。上記スライダーで横移動し、各時点の具体数字を縦ラインで確認。

### 3-4. 資金ショート警告（段階警告）
- **3段階**：余裕／注意／危険。
- **将来売上予測を組み込んだ上で**判定する（出費だけの判定にしない）。
- 安全資金ライン（経費○ヶ月分）を割り込む予測日をアラート。

### 3-5. 在庫の扱い
- 販売中の商品（まだ現金化していない資産）＝「**成約入金待ち**」として、**資産予測に別枠で含める**。
- 確定現金とは混ぜない（資金ショート判定は確定現金ベース、見込みは別枠参考）。

---

## 4. 精度の原則（厳守）

- **実測（確定）と予測（見込み）を必ず分離**して表示する（実線/点線、別枠表示）。
- 予測は「実績ベースの見込み」であり**断定しない**（「ショートしません」とは言わない）。
- 確定申告・利益確定の数字は実測（Finances API実額）を使う。予測は意思決定の補助のみ。
- 予測は月次で実額と比較し改善する（蓄積で精度向上）。

---

## 5. 順算・逆算・監視（3機能の整理）

| 機能 | 問い | 入力 | 出力 |
|---|---|---|---|
| 順算 | 今の資金でどこまで？ | 出撃可能資金 | 見込み売上・粗利・仕入れ可能数 |
| 逆算 | 目標にいくら要る？ | 目標粗利額 | 必要月商・必要出品数・必要資金 |
| 監視 | ショートしないか？ | CF予測 | 危険日・段階警告 |

※「率⇔額トグル」（利益計算機本体）と同じ双方向思想：資金も「資金→結果(順算)」と「目標→必要資金(逆算)」の両方向で見る。

## 6. 技術メモ（参考・未確定／黒が肉付け）

実装はSTAGE2完了後。以下は黒が現場知見で詰める領域。
- MF API：OAuth2.0/APIキーのどちらで連携するか。取得可能データ（残高・入出金・経費）の確認。アプリポータル登録・権限設計。

- CFタイムラインのグラフ実装（日次・期間可変・実線/点線・スライダー＋縦ライン数字）。
- データ保持スキーマ（資金設定・将来出費・予測係数・目標）。
